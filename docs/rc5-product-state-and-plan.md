# RC5 Product State And Plan

Date: 2026-05-13

## 1. 阁主判断

当前产品不缺“再加一个能力”，缺的是把已经跑通的能力收束成一条家长和孩子一眼能懂的晚间学习路线。

原点私教当前已经有一条可记、可测、可交付的主线：

孩子选一位老师 -> 发作业或说卡点 -> 排今晚第一步 -> 只修一个真实卡点 -> 小黑板只提示第一步 -> 孩子说出自己的第一步 -> 明天轻回访 -> 家长只问一句

RC5 的核心目标不是扩功能，而是继续压低旧的“知识游乐场 / 闯关 / XP / 报告墙 / 商业方案”外壳，让真机截图和体验路径都只呈现这条主线。

## 2. 当前状态

### 已成型

- Home / Review / Tools / Profile 四个 Tab 已通过 viewModel 承接首屏。
- `companionPreference` 已经能让六位老师贯穿四个 Tab。
- `tonightPlan / todayFocus / miniActionText / blackboardHint / reviewCard / profile summary` 的本地证据流已跑通。
- 原点小黑板已被限制为“第一步提示”，没有变成完整讲题工具。
- `miniActionText` 仍然是完成修复的必要门槛。
- `reviewCard` 能承接具体卡点、孩子第一步和小黑板提示。
- 自动测试和本地 `verify` 已经能守住主要行为边界。

### 仍然脆弱

- Tools 的历史形态来自“知识游乐场”，容易让用户误会成玩法合集，而不是回访页。
- Profile 下方还残留过游戏档案、成长报告、商业方案一类旧壳，很容易把“家长 5 秒复盘”重新拉回报告墙。
- 项目里仍有不少 legacy 页面和数据结构，首屏虽然已收束，但后续开发很容易误把旧表达带回主路径。
- `miniprogram/project.config.json` 仍是 `touristappid`，所以现在还不能上传体验版。

## 3. 能力 / 形态 / 不足

### 能力

当前最强的不是“学科讲解”，而是“晚间路线编排 + 卡点修复 + 学习证据沉淀”。

它真正能打的是：

- 把作业压力压成今晚第一步。
- 把“我不会”变成一个真实卡点。
- 让孩子必须说出自己的第一步。
- 让小黑板只提示先看哪里。
- 把修过的卡点沉淀成明天回访。
- 给家长一句不变成讲题的话。

### 形态

现在更像一个“晚间学习路线小程序”，不是通用 AI 助手，不是拍照搜题器，不是游戏化刷题平台，也不是家长数据后台。

四个 Tab 应该始终保持这套心智：

- 作业点拨：今晚先从哪一步开始。
- 轻回访：今天回访一小步。
- 修卡点：今晚只修一个真实卡点。
- 我的：家长只问一句。

### 不足

- 第二屏和更深层区域仍容易露出旧“挑战 / 报告 / 商业验证”语言。
- Tools 的“轻松练一下”虽然已经降权，但仍需继续守住“补位入口”而不是“产品主角”。
- Profile 里高级面板很多，后续若不加门禁测试，很容易再次滑回报告墙和运营后台口吻。

## 4. RC5 已执行

### 第一轮

- Tab 文案从“知识游乐场 / 错题闭环”收束为“轻回访 / 修卡点”。
- Review 完成态 CTA 改为“去轻回访”。
- Profile 首屏明确为“家长 5 秒复盘”。
- 新增 `scripts/test-rc5-product-shell.cjs` 并接入 `npm.cmd test`。

### 第二轮

- Profile 中“闯关复习”改为“轻回访”。
- 分享面板从“可分享的成长卡”改为“可分享的复盘卡”。
- 对比面板从“内容闯关”改为“内容回访”。
- 高级面板从“服务方案 / 免费体验 / 支付 / 课程售卖 / 访谈验证”收束为“上线准备 / 待真实测试 / 理解度检查”等非商业口径。
- Tools 的学习材料输出口径统一为“轻练习输出 / 生成轻练习”。
- RC5 壳层测试升级为同时检查 `app.json`、自定义 Tab、Review、Tools、Profile 的 `.wxml` 和 `.js` 数据源。

## 5. 下一步开发计划

### P0 不做

- 不新增 Tab。
- 不改后端 API。
- 不接 Qwen。
- 不做 OCR / PDF / PPT 导入。
- 不做完整讲题。
- 不做会员、支付、排行榜、PK、老师端。
- 不编造真实 AppID。

### P1 继续推进

- 继续把 legacy 页面标记清楚：哪些仍可见，哪些只作内部验证或后续清理。
- 在不破坏主线的前提下，进一步收紧 Profile / Tools 的高级区域，避免它们抢首屏和主 CTA。
- 真机前优先做 UI smoke checklist，盯住首屏高度、Tab 遮挡、文案断行、黑板提示可读性。

### P2 等真实 AppID 后

- 配置真实 AppID。
- 跑真机 UI smoke test。
- 根据真机截图再调字号、折叠关系和首屏信息密度。

## 6. 本轮验收标准

- 首屏主线仍是“今晚路线”，不出现 dashboard、系统诊断、老师分工或答案工具口吻。
- Tab 文案不再出现“知识游乐场 / 错题闭环”。
- Review 完成后下一步是“轻回访”。
- Profile 首屏仍是“家长 5 秒复盘”。
- Profile / Tools 深层可见文案不再出现“闯关 / 成长报告 / 服务方案 / 支付 / 课程售卖”等旧壳。
- `npm.cmd test` 和 `scripts/verify.ps1` 通过。
- 上传体验版仍被 `touristappid` 阻塞时，要明确说明这是当前唯一非代码门禁。
