# 原点智学 100 个孩子体验审查

更新时间：2026-05-09

## 结论

当前版本适合做「受控 100 人体验」的产品验证，但还不适合包装成完整 Gizmo 式线上社区产品。

可以验证的核心命题是：孩子把真实学习材料录入后，系统能否先用原小点追问出第一步，再通过回忆卡、小测、5 分钟闯关、FSRS 间隔复习和错因修复，让孩子愿意继续学，并在「我的」里看到可分享的真实进展。

100 人体验前必须明确边界：

- 展示本地进度、XP、生命值、连续天、可领取奖励和下一关。
- 不展示真实排行榜、好友挑战、班级竞争，除非正式云同步和身份体系已经上线。
- 不承诺拍照 OCR、文件上传识别、订阅通知和跨设备同步，除非微信与后端能力已经配置。
- 「我的」只看真实证据和分享卡，不显示商业化定价、内部飞轮和运营 SOP。

## 当前能跑通的链路

- 三主 Tab 已收敛为「原小点 / 知识闯关 / 我的」。
- 原小点首页能承接预习、学习、复习、错题，用追问和最小提示把孩子带到下一步。
- 知识闯关页能基于真实录入或本地 Storage 生成卡片、小测和待复习队列。
- 复习页已有游戏化循环：回忆卡、小测、评分、生命值、XP、连续天、奖励领取、FSRS 类间隔复习。
- 原小点已有内容安全前置检查，产品方向是提示下一步，不是直接给答案。
- 我的页能从本地任务、复习、错因和思考证据生成学习战绩与分享卡。
- 本地验证脚本通过，静态视觉审查截图能用于布局巡检。

## 100 人体验前必须解决

### 1. 正式身份

当前 `miniprogram/project.config.json` 仍是 `touristappid`。这会影响：

- openid_hash 聚合；
- 去重和留存分析；
- 100 人活动复盘；
- 跨设备同步；
- 后续真实班级榜或好友挑战。

体验版前必须配置正式 AppID、AppSecret、MINI_SESSION_SECRET，并确认 request 合法域名。

### 2. 云同步持久化

`api/mini/sync.js` 在未配置 Supabase 时会返回 `stateless_ack`。这对单机体验可以接受，但无法支撑 100 人后的留存、完成率、错因分布、分享漏斗和运营复盘。前端已避免把 `stateless_ack` 当成真实入云成功，但体验前仍应启用持久化。

100 人活动至少要持久化这些事件：

- material_imported
- priority_generated
- card_generated
- quiz_answered
- review_rated
- reward_claimed
- wrong_cause_repaired
- share_card_generated
- share_clicked
- learning_feedback_submitted

### 3. 学习反馈入库

`api/mini/feedback.js` 当前返回合同式回执，没有真实写库。100 人体验如果想知道哪里不准、哪些建议有用、分享后是否回流，必须把 feedback / learning_event 写入数据库。

最小字段：

- feedback_id
- client_id / openid_hash
- target_id
- rating
- reason
- calibration_key
- created_at

### 4. 真机 UI 验证

`scripts/miniapp-visual-audit.cjs` 生成的是静态 HTML 代理图，不等于微信真机证据。100 人前还要用微信开发者工具和手机体验版验证：

- iPhone/Android safe-area；
- 键盘弹起时聊天 composer 是否遮挡消息；
- 自定义 tabBar 点击和滚动；
- 长材料输入；
- 弱网、超时、429、接口失败；
- 首次进入空态是否能让孩子知道下一步。

## 刚修掉的阻塞

原先所有小程序 API 限流都按 IP 计数。100 个孩子在学校或机构同一个 Wi-Fi 下会共用出口 IP，容易互相触发 429。

现在已改为：

- 前端请求自动带 `x-mini-client`；
- 服务端 `clientRateKey()` 优先按 client 分桶；
- 没有 client 时按 session；
- 最后才按 IP 兜底。

这让 100 人同网体验从「高概率互相限流」变成「单设备独立限流」。

## 产品判断

原点智学的好机会不是复刻 Gizmo 的完整社交学习社区，而是在中国家庭晚间场景里做更窄、更刚需的闭环：

真实材料 -> 原小点追问第一步 -> 主动回忆卡 -> 5 分钟闯关 -> 间隔复习 -> 错因修复 -> 我的学习战绩。

这个方向能解决三个痛点：

- 孩子不知道从哪里开始；
- 孩子容易只看答案或刷题，没有下一次回访；
- 学习工具容易变成搜答案或堆题。

现在的产品已经有这个骨架。100 人体验的关键不是继续加页面，而是把单次路径压短：

1. 孩子进入首页，3 秒内知道「下一关」。
2. 录入材料不超过 30 秒。
3. 第一次闯关不超过 5 分钟。
4. 完成后立刻看到 XP、奖励和下一次复习。
5. 我的页立刻生成一句话进展、错因记录和可分享身份卡。

## Gizmo 对比

公开资料里，Gizmo 的核心能力是把 Quizlet、Anki、YouTube、PDF、Notes、PowerPoint、图片/手写笔记等材料转成 flashcards 和 quizzes，并用 active recall、spaced repetition、leaderboards、study games、public/shared decks 做学习动机。

这说明原点要学的是机制，不是营销承诺。体验营不要承诺「3 周 A+」或「10 倍效率」，先验证孩子是否愿意在真实作业场景里完成一轮 5 分钟主动回忆。

Gizmo 更强：

- 多格式导入和公开学习资料生态；
- AI 卡片与测验生成更成熟；
- 主动回忆与间隔复习路径更清晰；
- 社交、排行榜、公开 deck 更像网络化产品。

原点当前更强或更有差异：

- 更贴近中国家庭「今晚作业」决策；
- 家长证据闭环更明确；
- 错因修复比单纯背卡更适合提分焦虑场景；
- 原小点可以坚持不直接给答案，降低代写风险。

原点当前差距：

- 生产身份、云同步、活动分析未完全上线；
- OCR/文件导入能力不能宣称；
- 社交和排行榜不能宣称真实；
- 游戏化 UI 有了，但 5 分钟闯关还需要继续减少认知负担。

## 逆袭叙事怎么落地

Gizmo 的强叙事是「把枯燥学习变成停不下来的游戏」。原点不能只把 XP 和生命值贴在页面上，必须让游戏化服务学习闭环：

- 输入材料后立即产出第一组可玩的回忆卡。
- 每局只暴露一个目标：先答 3 题或复习 5 张卡。
- 答错不是惩罚，而是进入错因修复：概念不清、审题偏差、计算失误、表达不完整。
- 生命值用于节奏控制，避免孩子刷到疲劳。
- XP 和奖励只来自真实学习动作，不来自打开页面。
- 家长看到的是证据卡：今天做了什么、错因是什么、下一步是什么。

100 人体验的主文案可以是：

「今晚不刷 100 题。先用 5 分钟闯一关，把最该记住、最容易错的一点学会。」

不要使用：

- 3 周从不及格到 A+；
- 10 倍提分；
- 自动批改全部作业；
- 拍照秒出答案；
- 和全班好友实时 PK。

这些要么没有当前代码支撑，要么会把产品带回搜答案和焦虑排名。


## 体验营指标

建议 100 人体验只看这些指标：

- 首次录入完成率；
- 从首页到第一关开始率；
- 第一关完成率；
- 5 分钟内完成卡片数；
- 第二天回访率；
- 家长查看进展率；
- 家长反馈 accurate/off 比例；
- 孩子是否能说出错因和下一步。

不要用「分数提升」当首轮指标。第一轮验证的是动机、闭环和可信证据。

## Go / No-Go

Go：

- 正式 AppID 可用；
- request 域名配置完成；
- MINI_SESSION_SECRET 配置完成；
- Supabase 或同等数据库可写；
- 微信体验版真机主路径通过；
- 现场有失败兜底话术和手工收集表。

No-Go：

- 仍使用 touristappid；
- sync 仍只有 stateless_ack；
- 家长反馈不入库；
- 真机键盘或 tabBar 遮挡未测；
- 对外宣称排行榜、好友挑战、OCR、自动通知。
