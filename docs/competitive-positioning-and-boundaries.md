# Competitive Positioning And Boundaries

Date: 2026-05-13

## 1. Product Position

原点私教是面向中国家庭晚间作业场景的 AI 私教路线系统。

学校给全班同一份任务，原点私教给每个孩子一条自己的晚间学习路线；孩子今天选择谁，谁就陪他把这条路线走完。

路线是：

排顺序 -> 说第一步 -> 修卡点 -> 原点小黑板提示 -> 轻回访 -> 整理给家长看

前台体验统一成一句话：

孩子选择一位老师，老师陪他把今晚学习路线走完；遇到卡点时，不直接给答案，而是用小黑板帮他看清第一步，最后生成回访卡和家长只问一句。

## 2. Khanmigo: Safety Boundary

吸收点：

- 不直接给答案。
- 通过追问引导孩子先说出自己的第一步。
- 在孩子要求直接答案时拦截，并把任务拉回思考过程。

当前已有：

- tutor ladder：先追问、再提示，不把最终答案作为主路径。
- miniActionText：孩子必须用自己的话说出第一步，才能完成修复。
- 求答案拦截：无效或答案导向输入不能让修复 completed。

边界：

- 当前还不是 Khanmigo 级别。
- 还没有高质量学科理解。
- 还没有系统级安全评估、教师后台审查或完整对话安全基建。
- RC3 目标是晚间学习路线闭环，不是完整 AI 教师安全系统。

## 3. Gizmo: Active Recall

吸收点：

- reviewCard。
- active recall。
- 轻量回访，把学过或修过的内容用很短时间再想一遍。

当前已有：

- 修完 todayFocus 后生成 reviewCard。
- Tools 首屏只回答“今天回访一小步”。
- reviewCard 可以引用 todayFocus、miniActionText 和 blackboardHint。

边界：

- 当前还不是 Gizmo 级别。
- 还没有成熟 spaced repetition 算法体系。
- 还没有多格式导入、成熟卡组管理、跨设备复习档案。
- 原点当前只保留“修卡点 -> 明天回访”的本地证据流。

## 4. Nova: Companion Continuity

吸收点：

- 角色连续性。
- 陪伴感。
- 记忆感。

当前已有：

- 首页轻量展示六位老师。
- 孩子选择谁，谁就陪完整路线。
- companionPreference 全局影响 Home / Review / Tools / Profile。
- 阿衡等老师可以用“记得以前卡点”的陪伴语气，但不输出 dashboard。

边界：

- 老师是陪伴方式，不是功能分工。
- 不做“作业规划老师 / 错题老师 / 复习老师 / 家长老师”。
- 不做“数学老师 / 英语老师 / 语文老师 / 科学老师”。
- 不做老师六宫格大角色页，不让老师区抢主 CTA。

## 5. Qwen / 千问: Blackboard Inspiration

吸收点：

- 板书式、可视化提示的能力启发。
- 把抽象卡点变成“先看哪里”的提示结构。

当前实现：

- 原点小黑板。
- 只在错题闭环修复态出现。
- 只支持列式关系 / 读题审题 / 步骤断点 / 概念公式。
- 只输出第一步提示结构。

明确不做：

- 不套壳千问。
- 不跳转千问作为主路径。
- 不嵌入千问界面。
- 不做拍题讲解。
- 不做完整题目讲解。
- 不生成完整答案。

未来边界：

- 如果接 Qwen，只能作为底层能力层。
- 输出仍然必须是“第一步提示”。
- 不能跳过 miniActionText。
- 不能跳过 reviewCard。
- 不能把原点小黑板变成完整答案工具。

## 6. Yuandian Differentiation

千问强在“把题讲清楚”。

原点强在：

- 今晚怎么学完。
- 卡点怎么修。
- 明天怎么回访。
- 家长今晚只问哪一句。

原点不是弱版千问，而是晚间学习路线系统。

原点的核心闭环是：

学校作业 -> 个性化晚间路线 -> 先说第一步 -> 小黑板只提示第一步 -> 修完生成回访卡 -> 家长看到一句可问的问题。

## 7. Release Boundary

RC3 前台不应出现：

- 千问小讲堂。
- 千问讲题。
- 拍题讲解。
- 拍照出答案。
- 秒解。
- 答案已生成。
- 老师功能分工。
- 学科老师标签。
- dashboard。
- 错误类型分布。
- 内部 key / enum / source / stage。
