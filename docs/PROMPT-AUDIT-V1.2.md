# 阁主对当前 tutor-chat system prompt 的诊断报告

时间：2026-04-27 KA 化 4 段 ship 后
范围：`api/tutor-chat.js` 中 `buildSystemPrompt()` 函数生成的 prompt
当前规模：147 行 `L.push`，约 12,770 字（汉字）≈ 6,400 token

---

## 一、规模诊断 · 已经在临界值

DeepSeek-chat 的 context window 32k token 不会爆，但 **instruction-following 不是线性的**：

- 100-2000 token：所有规则被严肃执行
- 2000-5000 token：核心规则严格执行，边缘细则衰减 10-30%
- 5000-10000 token：开始出现「规则被忽略」「重要规则被次要规则盖过」
- 10000+ token：模型性能不稳定，输出风格摇摆

**当前 prompt 在 6400 token，刚跨进衰减区**。再加 5 条规则就进危险区。

下一步该做的不是再加，是**蒸馏 + 重排 + 合并**。

---

## 二、规则冗余审计 · 我看到的 7 处

### 2.1 「禁词」散在 4 个不同段落
- §0 语气铁律：禁 "**第一步** **注意** **重点**" + 客服话
- §5 动机心理 - Dweck：禁灌鸡汤
- §5.5 退场处理：禁「再坚持」「再做一题」
- §9 输出铁律 #6：禁「赋能 / 智能 / 一站式 / AI 驱动」

LLM 看到 4 张禁词清单时，会哪条都执行 60%。**应当合并成一段铁律级 「全局禁词清单」**，按出现概率降序排列。

### 2.2 「具体表扬」规则出现 3 次
- §5 SDT 胜任感：「具体表扬『你比上次多走对了 X 这一步』」
- §9 #3：「答对时具体表扬『对在哪一步』」
- §9 4a：「答案对但过程错追问」

后两条 cover 了第一条的所有场景。**第一条该删**。

### 2.3 算术铁律 + 4a 答案对过程错 边界模糊
两条都讲「数学正确性」但角度不同：
- 算术铁律：老师自己计算正确（防 DeepSeek 自己算错）
- 4a：判学生答案时检查推理过程（防夸瞎蒙对）

**该明确二选一时优先 4a**：因为 4a 是面向学生的产品行为，算术铁律是模型内部行为。让 LLM 优先把脑力放在判学生上。

### 2.4 「第一句铁律」与「专属档案」位置错
§10 第一句铁律给了 3 个示例（引用 stuckPts / 引用 emotion / 引用 weakKps），但 §2 学生档案部分已经塞了所有这些数据。LLM 在 §2 已经看到 stuckPts，到了 §10 又被告知怎么用——**间隔太远，LLM 忘了**。应当 §2 末尾直接接「→ 第一句开场」三例。

### 2.5 「≤80 字」与算术分步骤分行 直接打架
- §9 #1：单条 ≤ 80 字
- §9 算术铁律：方程解逐步骤分行写（每步一行 = 多行）

学生问「2x+3=11」时：4 行分步骤推导≈ 50 字，本身没冲突，但 LLM 看到第一条会优先「不超 80 字」，导致省略一步。**应明确：算术分步骤豁免 80 字**，标记为例外条款。

### 2.6 退场处理（§5.5）和 4b 要答案（§9 4b）
两条都教「学生不想做时怎么应对」：
- §5.5：累了 → 不挽留 + 留钩子
- §9 4b：要答案 → 1 分钟时限挑战

但学生说「直接告诉我答案吧不想想了」时，LLM 会困惑——是按 4b 给挑战还是按 5.5 接住「不想做了」？

**该加一条 routing**：「不想想了」=继续做但不想思考 → 4b；「不做了」=要走 → 5.5。

### 2.7 教学法 4 流派 + 动机心理 3 流派 太学术
§3 + §5 加起来 25 行 1500 字讲 Vygotsky / Bruner / Bloom / SDT / Dweck / Bandura。LLM 看完不会照念，但会被这些「学术 buzzword」轻微污染输出。

**蒸馏建议**：6 流派浓缩成 3 句行动指令：
- 永远在「踮脚够得着」推进难度
- 给最小提示让他自己迈一步
- 失败归到策略不归到天赋

## 三、推荐重构 · 「阁主版」prompt 骨架

如果要重写，按这 7 段结构（顺序很重要）：

```
§0 角色 + 语气                               (8 行)
§1 学生专属档案 → 第一句开场样本             (12 行)
§2 全局禁词清单（合并 4 处）                 (4 行)
§3 答题状态机：答对 / 答错 / 跳步 / 要答案 / 累了 / 闲聊
   每种 1 行触发条件 + 1 行响应模板           (12 行)
§4 长度铁律 + 算术分步骤豁免                 (3 行)
§5 教学法浓缩 3 行动指令                     (3 行)
§6 中国应试锚点                              (2 行)
§7 粘贴检测分支（仅在 isPasted=true 注入）   (8 行)
```

总规模 ~50 行 ≈ 2500 token。从 6400 砍到 2500，instruction following 从衰减区拉回严格区。

---

## 四、风险 · 重写 prompt 前必跑评测套件

任何 prompt 改动必须满足：
1. 改前先跑 `bash scripts/eval-all.sh` 拿 baseline
2. 改完跑同一条命令拿新分数
3. 任一项跌出 5% → 撤回

否则我们没办法证明「重写后真的更好」。**当前没有 baseline**——哪怕 KA 化 4 段那 5 个 commit 改了 prompt 都没量化前后差。这是一笔技术债。

---

## 五、当前优先级 · 先 baseline 再重写

具体顺序：

1. **现在**（你做）：跑一次 `eval-all.sh` 拿当前 prompt 的真实通过率
2. **拿到数据后**（我做）：按本文 §三的骨架重写 prompt，单一 commit
3. **验证**（你做）：再跑一次 eval-all 对比
4. 任意 ABCD 一项跌 5% → revert 那个 commit，本文档作废
5. 全升 → ship 重构

**不在顺序里：现在凭直觉重写**。这种重构成功率不到 50%，没有数据兜底就是赌。
