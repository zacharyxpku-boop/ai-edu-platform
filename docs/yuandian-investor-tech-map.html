投资人应该先理解的事

家长不是缺工具，是缺“今晚怎么安排”的确定感。
孩子不是需要 AI 直接给答案，而是需要在关键一步被扶一下。
数据不是从大模型来，而是从真实测评、错题、作业取舍和对话里沉淀。
微信小程序是低成本承接入口，官网和内容负责获客，小程序负责留存和转化。

产品闭环
从工具到陪练的数据飞轮

每天可重复的核心闭环

我们不把产品做成“功能超市”。首版只保留能产生连续数据和真实价值的闭环。

1

测评/试卷/作业录入

用户手动输入成绩、错题描述、作业清单；照片先做本地留档，不承诺自动识别。

2

生成能力雷达

把学习问题拆成概念、计算、审题、迁移、表达、负荷六个维度。

3

作业三分类

让孩子先做最有价值的部分，而不是把精力平均摊在所有题上。

4

原小点思路陪练

只处理高优先级任务和关键错因；先问思路，再给最小提示。

5

家长看反馈

家长看到的是弱点、取舍和进步证据，不默认读取孩子完整对话。

必须做 40-50%

命中当前弱点、老师课堂核心、近期反复错。不做完会拖累后续学习。

灵活选择 20-30%

有帮助，但可根据今晚时间和精力取舍，避免过度消耗。

可以跳过 20-30%

机械重复、已掌握、低收益任务。跳过不是偷懒，是保护精力。

技术架构
轻量上架，重资产沉淀

三层架构：入口轻，算法可演进，数据可沉淀

首版用最低成本跑通真实用户闭环；长期价值来自学习数据、错因数据和对话记忆，而不是页面数量。

用户入口层

官网承接内容、工具、品牌和留资。
微信小程序承接高频使用：今日决策、工具、雷达、原小点。
家长端看弱点、作业取舍和进步证据。
运营端看留资、数据和内测反馈。

学习智能层

作业优先级算法将任务拆成必须做、灵活选、可跳过。
错因诊断把错误归因到概念、审题、迁移、表达等维度。
AI 陪练服务端调用模型，拒绝代写，给最小提示。
掌握度与复习BKT / FSRS 为后续个性化推荐提供基础。

数据资产层

Supabase/Postgres学生状态、错题、对话、复习状态。
知识图谱按学科、年级、章节组织知识点。
对话记忆沉淀孩子常见卡点、学习风格和兴趣线索。
安全合规小程序隐私授权、内容预检、服务端模型调用。

Mind Map04 / 05
路线与壁垒
Now / Next / Later

从小程序 MVP 到学习数据资产

Now

低成本上架

原生微信小程序、官网 API、小程序审核材料、一键预检脚本。首版不做支付、不做 OCR、不碰复杂教育资质。

Next

真实用户验证

验证家长是否每天打开、孩子是否愿意继续做、作业三分类是否真的减少无效消耗。

Data

沉淀学习画像

形成孩子的弱点轨迹、错因库、作业选择偏好、对话记忆和复习节奏。

Scale

扩展商业化

接入微信登录、家长绑定、官方内容安全、OCR/试卷识别、付费服务和线下/社群转化。

为什么不是大模型套壳

大模型负责语言和引导，但系统价值来自学习流程设计、错因结构、作业优先级和长期数据沉淀。

为什么有壁垒

同一个孩子长期使用后，会沉淀专属弱点、错因、节奏和家长反馈，形成可复用的数据资产。

当前阶段的核心目标：不是一次性做全功能教育平台，而是用微信小程序跑通“每天晚上帮家长和孩子做学习取舍”的高频闭环。
