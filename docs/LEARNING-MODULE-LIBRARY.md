# 学习模块库 v1

## 定位

学习模块库不是 prompt 收藏夹，而是把适合学习的 AI 使用方法产品化成可点击模块。

每个模块必须回到原点智学闭环：

```text
学习场景 -> 用户输入 -> AI 任务 -> 掌握证据 -> 原小点执行 -> 家长复盘
```

## 方法来源

模块吸收的是通用学习科学和 AI 学习建议中的稳定原则：

- 苏格拉底式提问：不直接给答案，先追问思路。
- 脚手架教学：先给结构，再逐步撤掉提示。
- 主动回忆：闭书回答比反复重看更能检测掌握。
- 错误分析：把“粗心/不会”拆成可修正错因。
- 间隔复习：把掌握检查拆到今天、明天和几天后。
- 元认知反思：让孩子说出卡点、下一步和复盘句。
- 人类监督：家长看到掌握证据和复盘话术，而不是只看 AI 输出。

这些原则来自公开 AI 教育实践、学习科学和高校/机构对学生使用生成式 AI 的建议。产品中不直接承诺提分，只承诺提高学习任务决策、练习质量和错因复盘的可见度。

## 产品原则

1. 不做散乱提示词。
2. 不承诺 30 天学会任何技能。
3. 每个模块必须有掌握标准。
4. 每个模块必须能进入原小点执行。
5. 内测后按真实作业高频场景扩展。

## 推荐逻辑

模块库已经接入雷达页。系统会根据以下信号推荐 2-3 个学习模块：

- 当前学科
- 雷达弱点名称和原因
- 作业三分类文本
- 错因关键词
- 时间/负荷相关描述

推荐不是为了展示更多内容，而是把模块库接回主闭环：

```text
雷达弱点 -> 推荐模块 -> 模块详情 -> 原小点执行 -> 掌握证据 -> 家长复盘
```

## 行为记录

小程序本地记录两类模块行为：

- `module_viewed`：用户打开模块详情
- `module_started`：用户从模块进入原小点
- 模块反馈：`useful` / `not_useful`

记录字段：

- 模块 ID
- 模块标题
- 学科
- 模块类型
- 来源：`tools_library` 或 `radar_recommend`
- 时间

这些记录只用于内测阶段判断哪些学习方法被真实使用，不接第三方追踪，不用于广告投放。个人页会展示浏览次数、开始次数和高频学科。

推荐引擎会使用本地模块反馈做轻量校准：

- 被标记“适合现在练”的模块会加权。
- 被标记“暂时不适合”的模块会降权。
- 反馈只保存在本机，首版用于内测观察，不作为广告追踪。
