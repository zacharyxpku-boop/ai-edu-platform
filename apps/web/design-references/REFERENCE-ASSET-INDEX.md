## Reference Priority

1. GPT six-screen reference is the target shape for this Web surface.
2. Current Web preview screenshots are evidence of what the implementation actually renders.
3. Competitor screenshots are inspiration, not copy targets.
4. Variant code can be used only as a local Web implementation reference and must not be pasted into `miniprogram/`.

## Competitor Lessons To Preserve

| Competitor/source | What to learn | What not to copy |
| --- | --- | --- |
| Duolingo | A clear first action, strong character presence, streak/reward loop | Over-simplifying parent-facing evidence into pure gamification |
| Synthesis | A playful challenge map and high-energy CTA | Hiding evidence and learning purpose behind entertainment |
| Khan / Khanmigo | Guided learning and Socratic tutor boundary | Generic chat UI or direct-answer behavior |
| ClassDojo | Parent-readable progress and family communication | Social-feed density or classroom-only framing |
| Quizlet | Review modes and active recall | Static flashcard walls without wrong-cause repair |
| Xueersi / Banma / Xiaoyuan / Zuoyebang | Chinese family education entry density, course/task cards, homework upload expectations | Turning the Web app into a generic course mall or answer-checking tool |

## Visual Acceptance Rules

- Every page must show one active job and one obvious next route before the user scrolls.
- The Web shell must keep the six-entry frame: left nav, top search/student/family bar, main page, right contextual rail.
- Upload must explain material intake and evidence classification, not just file storage.
- Report must show evidence and confidence before method recommendation.
- Tutor must show first-step guidance and answer-safe boundaries, not a generic chatbot.
- Review must show memory, transfer, and variation as distinct learning purposes.
- Parent must answer: what happened, what changed, what should I ask tonight?
- Mobile must not turn into one long dense scroll before the first real action.
