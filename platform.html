自研引擎 · 不是套壳
三个独立 pipeline，每个都能单独作为 API 对外提供或被第三方接入。
pipeline · python
教材抽章管道
scripts/fetch-textbook.py → extract-chapters.py → ocr-scan-textbooks.py → gen-textbook-manifest.py。四段式管道把 raw PDF 变成按章的 JSON，正文 + 小节 + 起止页全结构化。
  • born-digital: PyMuPDF + 字号启发式（≥60pt=章, ≥24pt=节）
  • 扫描件: rapidocr-onnxruntime 离线跑，单本 ~12 分钟
  • manifest 前端实时 fetch，0 后端依赖
python scripts/fetch-textbook.py 高中 历史 统编版 --all python scripts/extract-chapters.py --all-downloaded python scripts/gen-textbook-manifest.py
engine · POST /api/chapter-match
章节匹配引擎
给一道题 → 秒级找到最匹配的教材章节。规则层 = 子串 + 3-gram + alias + kp 前缀 + 阈值。对比通用 LLM RAG：可解释、0 token、<30ms。
  • 加载中 · 反链命中率
  • 10 学科 alias 字典，自研 K12 语料标注
  • Vercel edge runtime，manifest 内存缓存
fetch('/api/chapter-match', { method:'POST', body: JSON.stringify({ subject: 'physics', chapter_hint: '光学', knowledge_points: ['凸透镜成像'] }) }) 试一下引擎 ↓
pipeline · deepseek · python
章节→练习生成管道
读章节正文（截 3500 字）→ 调 DeepSeek 按严格 JSON schema 生 3 题/章（易中难各 1）→ 增量落盘 + 失败可重入。章节扩学科只需扒教材，题库随之扩。
  • 268 章全量运行约 25 分钟 / 268×3=804 题
  • done_map 去重，断点续跑不重复消耗 token
  • response_format=json_object 锁结构，脏数据率 <1%
python scripts/gen-questions-from-chapter.py \ --subject 数学 --stage 初中 --limit 20
model · BM25-jieba · 1.8 MB · 浏览器内
章节检索模型 v1
jieba 分词 + Robertson BM25 在 284 章语料上构索引。索引产物 1.8 MB JSON 一次性 fetch 进浏览器，每次查询 0 token、<30 ms、离线可用。给"用文字描述找最相关章节"开自研入口。
  • 词表 9893 项 · IDF 全量缓存
  • 查询端 char 2/3-gram 反查 vocab，无需带 jieba 进客户端
  • 对比 OpenAI embedding：0 月费 + 全离线 + 可解释
import { loadBM25, queryBM25 } from '/src/models/bm25-runtime.js'; const idx = await loadBM25(); queryBM25(idx, '凸透镜成像规律', { k:5 }); 试一下模型 ↓
