8 学科 ensemble 命中率分布
按学科横向看每套引擎的命中率。物理/地理/生物 ensemble >93% 接近上限；语文最弱 78%——OCR 把"第N单元 XX"截成"第N单元"，索引信息密度不足。这是数据问题，不是模型问题，下一步是优化语文章节标题清洗。
w_rules 权重扫描曲线
融合时 rules 分数的权重 w 从 0（纯 BM25）扫到 5。曲线单调上升说明 rules 信号始终带正贡献。w=5 是当前最佳点，再大反而会让 rules 分数饱和的 chinese 学科退步。
在线试跑 · /api/chapter-ensemble
不用 clone 仓库不用跑评测，直接 POST 一个题目，0.5s 内拿到融合预测的 top-5 章节、子分数、命中 alias/kp、引擎版本号——和评测脚本走的是同一份代码路径。或者去 /search.html 用更友好的界面查，附章节正文片段。

复现指引
所有评测脚本、模型索引、生题数据集都在 GitHub。下面四条命令即可复现 89% 的数字。

1. 拉代码 + 装依赖

git clone https://github.com/zacharyxpku-boop/ai-edu-platform
cd ai-edu-platform
pip install jieba
→ GitHub 仓库

2. 重建 BM25 倒排索引（可选）

PYTHONIOENCODING=utf-8 python \
  scripts/build-chapter-bm25-index.py
# 输出: src/models/chapter-bm25.json (1.8MB)
→ build-chapter-bm25-index.py

3. 跑 BM25 单引擎评测

PYTHONIOENCODING=utf-8 python \
  scripts/eval-bm25-recall.py
# Recall@1 63.0% / @5 93.5%
→ eval-bm25-recall.py

4. 跑 ensemble 融合评测

PYTHONIOENCODING=utf-8 python \
  scripts/eval-ensemble.py
# Recall@1 89.0% w_rules=5.0
→ eval-ensemble.py
数据诚实说明

评测集 843 道由 DeepSeek 按章节文本生成 → gold textbook_ref 和章节是同源对齐，存在系统性"近源偏差"。换句话说，这个 89% 是引擎在同分布数据上的天花板，真实用户随手写的非典型题（错别字、跨章节复合题）会比这个数低。下一步在做跨分布盲测集——拿真实初高中考试卷扫描件做 100 道独立 hold-out，那个数字才是用户最终体感。我们会把它公开放在这个页面上。

这套基准证明了什么
不是把 LLM 包一层壳。是教育领域最朴素的事——把 24 本教材 OCR 干净、把 843 道题对齐到章节、用规则+检索两条独立路径互证、把整条管线开源。

0 次 LLM 调用

从用户输入题目到返回章节，整条路径不调 GPT/Claude/DeepSeek。毫秒级响应，零 token 成本，零数据外送。

1.8MB 浏览器跑

BM25 索引 1.8MB gzip 后 600KB，在浏览器端用 ES module 异步加载，端上做检索不依赖任何后端。

843 道公开盲测

竞品报数字一般不放评测集。我们把生成数据集、评测脚本、报告 JSON 全部开源，你可以一行命令复算。

+44pp 引擎互补

融合相对单纯 rules 引擎 +44.5pp，相对单纯 BM25 +26pp——证明两条路径不是冗余，是真互补。
